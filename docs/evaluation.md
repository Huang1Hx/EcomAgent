# 发布评测口径

本文件说明 `make eval-release` 如何汇总证据，以及当前报告能、不能支持哪些表述。
原始产物在 `data/eval/reports/`，单项报告仍由各自评测器生成。

## 一条命令看到全部状态

```bash
make eval-release                 # 按 contract→unit→rag→intent→agent→flywheel→classifier→context 顺序运行
make eval-release ARGS="--aggregate-only --skip-flywheel"   # 只聚合现有报告(不调用模型)
```

聚合器只读取各阶段报告，不重算指标、不改答案和阈值。阶段状态只有：
`passed`、`failed`、`provider_error`、`service_unavailable`、`not_run`、
`stale_report`、`invalid_report`、`blocked`。总状态取最严重的一项，
**未运行或上游错误永远不算通过**。

产物：

| 文件 | 内容 |
|---|---|
| `data/eval/reports/release-eval.json` | 每阶段状态、命令、报告路径、分子/分母与 Wilson 95% 区间 |
| `data/eval/reports/release-eval.md` | 同一结果的可读版本 |
| `data/eval/reports/project-evidence.json` | 七项能力的 `supported` / `partially_supported` / `unsupported` 映射 |
| `data/eval/reports/project-evidence.md` | 证据映射的可读版本 |

报告记录生成时间、Git SHA、数据集 SHA256、模型名与阈值。数据 SHA 与当前
`data/eval/*.jsonl` 不一致时标 `stale_report`；报告格式不满足对应阶段要求时标
`invalid_report`。

## 数据集与审核状态

- 旧 `tests/data/eval_ch04.jsonl` 300 题只作开发回归，报告标 `development_only`，
  不能用于独立测试结论。
- `data/eval/` 下的盲测、意图、Agent、飞轮和上下文集均为 AI 辅助编写或模板生成，
  当前元数据仍为 `review_status=ai_assisted_unreviewed`、`reviewers=0`。用户确认曾抽检，
  但样本 ID、数量、覆盖和结论尚未形成台账；目前只能作为开发/回归证据，不能写成
  “整套数据逐条人工审核”或“独立发布证据”。记录方式见
  [人工抽检记录模板](eval-human-audit-template.md)。
- 置信度校准集与盲测集按锚点隔离。校准集只选阈值；盲测集只报告固定阈值下的
  误放率、误拦率及 95% 区间，不回调阈值。
- 飞轮闭环只在独立 MySQL 库与独立 Milvus 集合运行，不得写真实业务库。

## 阶段与当前证据边界

| 阶段 | 通过条件 | 说明 |
|---|---|---|
| 数据合同 | `tests/test_eval_dataset_contracts.py` 全部通过 | ID、字段、split、去重、支持数与 manifest 哈希 |
| 单元测试 | 全量 `pytest` 通过 | 2 条分类器 live 测试默认跳过，不算通过 |
| RAG 盲测 | 盲测数据匹配、检索与生成/拒答完整、无上游失败或跳过题 | 仅检索完整时阶段为 `not_run` 或 `provider_error`，检索能力只标 partially；499/429/超时不计成答错或正确拒答 |
| 在线意图 | 当前聚合器要求全部标注题判对且无上游错误 | 输出混淆矩阵与每类 P/R/F1；205/222 是有效诊断，但阶段仍为 `failed` |
| Agent 多轮 | 当前聚合器要求全部题通过、无上游错误 | 校验工具、顺序、动作、结果与订单归属；135/153 不等于发布通过 |
| 飞轮闭环 | 隔离报告、数据 SHA 一致、全部评测题通过且无写回问题 | 当前 46/50 未过门槛；50/50 写回不能代替首轮入池与完整闭环 |
| 17 类分类器 | 报告权重 SHA 与校验后的 bundle 一致 | 现有 v1 测试集回归，不是新独立盲测 |
| 上下文固定集 | 确定性三层装配全部通过 | 不调模型；报告事实保留率、错误继承率、平均估 token 与装配 p95 |

## 对外表述规则

- 对外宣称“通过”只引用 `release-eval.json` 中 `passed` 且数据/模型版本与当前仓库一致的分子/分母；
  `failed` 或 `not_run` 阶段的已完成子项可作为明确标注的诊断数据展示，但不能写成阶段通过或最终成绩。
- 旧简历或历史章节中的准确率，只能在该阶段当前证据为 `passed` 时沿用；
  否则写成“历史结果，当前未复现”。
- “人工复核”只用于确实逐条复核过的样本；AI 辅助未审核数据不得使用该表述。
- 总状态不是 `passed` 时，写明未通过/阻塞阶段与原因，不写成“全链路验收完成”。
- 当前意图、Agent、飞轮阶段未过门槛，原因是各有实际未通过题目；
  `ai_assisted_unreviewed` 是额外的证据限制，不能拿它代替这些失败原因。

## 等待上限与小样入口

- `RAG_CALL_TIMEOUT` 控制生成、覆盖度/忠实度裁判、D 桶拒答和单次检索的等待上限，
  默认 **60 秒**（历史 45 秒曾截断慢裁判，120 秒会让失败整轮拖得更久）。
- `RAG_NOTE_TIMEOUT` 控制“读图小注”的单条等待，默认 **30 秒**，并且小注串行生成；
  小注失败只回落页面兜底句，不进入生成段分母。
- `RAG_EVAL_LIMIT=N` 按文件顺序只取前 N 题，用于在限流前验证链路；报告 `meta.eval_limit`
  记录实际抽样，不能把这种小样结果当作全量 396 题成绩。
- 检索自身也有超时；超时按上游失败中止（`provider_error`），不会变成答对或正确拒答。
- 超时只解决单次等待上限，不等于整轮吞吐已达标。共享上游时生成并发保持 1，
  提高并发必须另做小样对比并记录 429/499。

## 检索诊断与 D 桶口径

`scripts/rag_diagnosis.py` 离线核对题集分桶、锚点、分母和已存报告；加
`--with-retrieval` 才走嵌入/重排，不发聊天请求。产物写到 `/tmp/rag-diagnosis/`，
不覆盖 `data/ch04/reports/` 下的发布报告。
`data/eval/reports/rag-retrieval-diagnosis.json` 是对已有命中缓存按正式证据组口径
离线重算的诊断证据：包含数据 SHA、命中缓存 SHA、逐题名次和指标分子/分母，
可从入库的逐题名次复算 248.5/282 与 MRR 0.5919。原始命中缓存不在 Git；
若要复验检索事实，需在相同知识库和嵌入/重排配置下重新运行检索，可能产生不同结果。
这份诊断不是生成/拒答全链通过报告。

### 为什么旧数字与当前页面不同

历史 300 题是参与过调优的开发集：A/B/C/E 四个可答桶各 60 题、D 库外桶 60 题，
当时混合加精排的 Recall@5 为 0.983、MRR 为 0.894，端到端答案覆盖度 0.974、
库外在线拒答 60/60。这些只属于当时的开发集与模型/知识库快照，不能写作当前成绩。
当前 396 题集的可答桶为 60/70/60/92，库外桶 114；与旧集 query 无完全相同项，
当前入库检索报告为 Recall@5 0.881、MRR 0.593。型号桶和跨文档桶的变化最大；
知识库块数也从 51 变为 52。不同题集、知识库快照和运行时间混在一起，不能据此
断定检索算法本身退化；要判断代码回归，须在同一题集、同一知识库和同一嵌入/重排配置下对照。

2026-10-19 20:40 的本地 RAG 报告在 `gen:vector:RAG-B-A-退货政策` 单次等待
60 秒后以 `TimeoutError` 中止，`generation=null`。页面因此不显示本轮端到端答案覆盖度
和库外在线拒答率，这是“未测出”，不是零分。报告另存固定阈值的生成前门控诊断：
114 道库外题均被门控拦截，但它不经过完整在线回答/自检链，不能替代库外在线拒答率。
该超时报告尚未纳入 Git，最终发布结论仍以版本化报告和聚合状态为准。

D 桶旧口径只看 `sufficient`：FAQ 返回 `sufficient=True` 就记“误放”。修订口径把
“检索到证据、证据明确说明不能给准数、最终答复没有具体承诺”记为解释性拒答成功，
把“证据不足”或“最终答复仍承诺具体天数”单列为失败。两套口径分开记录，
旧报告不改写；阈值只能在开发/校准集上调整，盲测集只报告固定阈值结果。
